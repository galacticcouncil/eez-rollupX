# Local EEZ L2

L2 **424242** runs on [local L1/PBS](PBS.md) with
[Hydration rules](../../../../docs/hydration/local-devnet.md) enabled at genesis.
It uses the independent ECDSA signer. All commands run from the repository root.

## Images

Reuse matching existing node/signer/deploy images. To build them once from the
checked-out source and initialized protocol pin:

```sh
revision=$(git rev-parse HEAD)
protocol=$(git ls-tree HEAD eez-core-protocol | awk '{print $3}')
tag=${revision:0:8}
sudo docker buildx build --builder default --platform linux/amd64 \
  --resource cpu-period=100000 --resource cpu-quota=800000 \
  --resource memory=32g --resource memory-swap=32g \
  --build-arg BUILD_PROFILE=release \
  --label org.opencontainers.image.revision="$revision" \
  --label io.eez.protocol.revision="$protocol" \
  --load -t "eez-devnet-node:$tag" .
sudo docker buildx build --builder default --platform linux/amd64 \
  --resource cpu-period=100000 --resource cpu-quota=800000 \
  --resource memory=32g --resource memory-swap=32g \
  --build-arg BUILD_PROFILE=release \
  --label org.opencontainers.image.revision="$revision" \
  --label io.eez.protocol.revision="$protocol" \
  --load -f Dockerfile.signer -t "eez-devnet-signer:$tag" .
sudo docker buildx build --builder default --platform linux/amd64 \
  --build-arg "EEZ_NODE_IMAGE=eez-devnet-node:$tag" \
  --build-arg FOUNDRY_VERSION=v1.7.1 \
  --label org.opencontainers.image.revision="$revision" \
  --label io.eez.protocol.revision="$protocol" \
  --load -f testing/kurtosis/Dockerfile.deploy -t "eez-devnet-deploy:$tag" .
sudo docker image inspect "eez-devnet-node:$tag" "eez-devnet-signer:$tag" \
  "eez-devnet-deploy:$tag" --format '{{.Id}} {{json .RepoTags}}'
```

Build sequentially to bound memory use. These are local development images;
Lark/Chiado require the verified published release artifacts.

## Deploy once and start

Select the existing image tag, then deploy:

```sh
tag=YOUR_IMAGE_TAG
sudo env "EEZ_DEVNET_DEPLOY_IMAGE=eez-devnet-deploy:$tag" \
  bash scripts/local-devnet.sh l2-deploy
sudo docker service ps eez-devnet-l2-deploy_deploy --no-trunc
sudo docker service logs --tail 100 eez-devnet-l2-deploy_deploy
```

Require `Complete` with exit 0 before starting:

```sh
sudo env "EEZ_DEVNET_NODE_IMAGE=eez-devnet-node:$tag" \
  "EEZ_DEVNET_SIGNER_IMAGE=eez-devnet-signer:$tag" \
  bash scripts/local-devnet.sh l2-start
sudo bash scripts/local-devnet.sh l2-status
```

Deployment renders/binds genesis, deploys the pinned Core and registers rollup 1.
A persistent start marker blocks automatic rebroadcast after partial failure.
Inspect receipts rather than rerunning deployment. Runtime startup checks the
saved public documents against their checksums.

## Fees and quotes

The base stack disables application settlement fees; ordinary L2 gas fees remain.
The cross-chain suite requires quotes in both directions. Enable the synthetic
private-network profile with the **same images**:

```sh
sudo env "EEZ_DEVNET_NODE_IMAGE=eez-devnet-node:$tag" \
  "EEZ_DEVNET_SIGNER_IMAGE=eez-devnet-signer:$tag" \
  docker stack deploy --detach=true --resolve-image never \
  -c deploy/swarm/local/stacks/l2.yml -c deploy/swarm/local/stacks/l2-fees.yml eez-devnet-l2
```

This restarts Composer; wait for rollout/catch-up. The overlay uses test ETH parity,
zero fixed costs/risk, a 20% profit allowance and 90% L1 refund request.
It is not Lark pricing. Daily `up` preserves the installed profile.
`l2-start` reapplies the fee-disabled base; doing so deliberately rolls collection
back without reversing historical fees. Reconcile unsettled requests after either restart.

## Interfaces

On the private `eez-devnet_l1` overlay:

| Endpoint | Purpose |
| --- | --- |
| `http://eez-node:18688` | Standard L2 RPC, including `debug_*` |
| `http://eez-node:18999` | L1 cross-chain front |
| `http://eez-node:18998` | L2 cross-chain front and `eez_*` observations |
| `http://eez-beacon:5252` | Dedicated L1 beacon API |
| `eez-proof-signer:50061` | Internal prover gRPC |

Embedded L1 RPC is loopback-only inside Composer at `127.0.0.1:18545`.
No L2 host ports are published.

## Counter canary

This spends public fixture gas and increments the native counter:

```sh
sudo env "EEZ_DEVNET_DEPLOY_IMAGE=eez-devnet-deploy:$tag" \
  docker stack deploy --detach=true --resolve-image never \
  -c deploy/swarm/local/stacks/l2-canary.yml eez-devnet-l2-canary
sudo docker service ps eez-devnet-l2-canary_canary --no-trunc
sudo docker service logs eez-devnet-l2-canary_canary
```

Require `Complete`/exit 0 and `PASS`: the canary checks execution and canonical
L1 commitment advancement. Use [cross-chain validation](VALIDATION.md) for both
directions, nested calls and independent blob checks.
Reset includes this canary. The one-shot job does not rerun on an unchanged stack
deploy; an intentional new run uses `sudo docker service update --force --detach=true eez-devnet-l2-canary_canary`.

## State and recovery

| External volume | Contents |
| --- | --- |
| `eez-devnet-424242-deployment` | Genesis, profile, public bindings and markers; runtime mounts read-only |
| `eez-devnet-424242-broadcast` | Foundry receipts, including partial deployment |
| `eez-devnet-424242-node` | L2, embedded L1 and witness data |
| `eez-devnet-424242-beacon` | Dedicated consensus follower data |

Use [whole-network lifecycle commands](../README.md#run-check-and-stop).
Keep all four volumes with their paired L1/PBS state and Engine JWT. Never share
writable execution/beacon datadirs between roles. Accepted queues are in memory;
volumes do not guarantee their recovery.

Chain IDs or Hydration role changes require a fresh network. For incompatible
upgrades, follow the [manager/key procedure](../../../../docs/runbooks/chiado-deployment.md#rollup-manager-and-coordinated-upgrades).
Use the [validation guide](VALIDATION.md) for cross-chain checks and their scope.
